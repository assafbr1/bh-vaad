חלק א: סנכרון נתוני דאשבורד התיקים לאתר הגיבוי (נוהל מ-26.10.2026: פרוסות לענף build ופרסום אוטומטי)

רקע: קובץ הנתונים המוצפן data.enc.txt הוא כ-50,000 תווים, והעברה שלו בקריאה אחת של push_files נכשלת או משתבשת (קטיעה, חסימה, או קובץ חלקי). לכן הקובץ מפוצל לפרוסות של עד 10,000 תווים, כל פרוסה נדחפת בקריאה נפרדת לענף build-* (לא ל-main), והפעולה האוטומטית publish-build (.github/workflows/publish-build.yml במאגר) מאחה את הפרוסות, מאמתת sha256 ו-JSON, מפרסמת את data.enc.txt ל-main ומוחקת את הענף. בלי התאמת sha256 שום דבר אינו מתפרסם.

1. קרא מבסיס הנתונים של דאשבורד התיקים בכלי ArtifactData (טען עם ToolSearch "select:ArtifactData"): list על cases (query.limit 1000, עם out_dir), list על deadlines (עם out_dir), list על docs (עם out_dir), ו-get על collection meta עם doc_id changelog. כל קובץ JSON מכיל את המסמך תחת השדה data. קרא מחדש גם אם קראת בחלק 0א, כדי לכלול את מה שנכתב שם. אם הקריאה נכשלת או שמספר התיקים קטן מ-300, עצור את חלק א בלי להעלות דבר, סמן partial והמשך לחלק ב.
2. בנה בפייתון את payload.json: {"cases": [...], "deadlines": [...], "docs": [...], "changelog": השדה entries מתוך meta/changelog, "exportedAt": הזמן הנוכחי ב-ISO עם Z}, בקידוד UTF-8 ו-ensure_ascii=False.
3. כלים: git clone --depth 1 https://github.com/assafbr1/tikim-dashboard.git לתיקייה מקומית (שכפול לקריאה; המאגר ציבורי). הסקריפטים בתיקיית tools של השכפול: make_data_parts.py (הצפנה ופיצול) ו-verify_site_data.py (אימות ופענוח). אם pip חסר את cryptography, התקן עם pip install --break-system-packages cryptography.
4. הצפנה ופיצול: python3 <שכפול>/tools/make_data_parts.py --payload payload.json --password '<הסיסמה>' --out <תיקיית פלט>. הפלט: data.enc.txt (gzip ואז AES-256-GCM, מפתח PBKDF2-SHA256 ב-300000 איטרציות, salt 16 בתים ו-iv 12 בתים אקראיים, JSON בשורה אחת עם salt, iv, ct, iters, gzip, exportedAt), data.enc.sha256 (ה-sha256 של הטקסט), והפרוסות data.enc.part-00.txt, data.enc.part-01.txt וכן הלאה. רשום את מספר הפרוסות ואת תוכן data.enc.sha256.
5. ענף: שם הענף build-YYYYMMDD-tikim לפי התאריך ב-UTC. צור אותו עם create_branch של GITHUB (owner assafbr1, repo tikim-dashboard, from_branch main). אם הענף כבר קיים (שריד מריצה שנכשלה), השתמש במקום זאת בשם build-YYYYMMDD-tikim-b (ואם גם הוא קיים, -c).
6. דחיפה, קובץ אחד בכל קריאה של mcp__GITHUB__push_files (branch הוא ענף ה-build, לעולם לא main), בסדר הזה: קודם data.enc.sha256, ואחריו הפרוסות לפי הסדר data.enc.part-00.txt, data.enc.part-01.txt וכן הלאה עד האחרונה. את תוכן הקובץ קח מהקובץ עצמו (הדפס אותו בבאש עם cat והעתק את הפלט כפי שהוא לשדה content, בלי להוסיף רווחים, ירידות שורה או הסברים; כל פרוסה היא שורה אחת של עד 10,000 תווים). אחרי כל דחיפה אמת אותה: get_file_contents של GITHUB עם owner assafbr1, repo tikim-dashboard, path <שם הקובץ>, ref refs/heads/<ענף ה-build>; ה-SHA שבשורה "successfully downloaded text file (SHA: ...)" (או ה-sha שבפרטי הקובץ) חייב להיות זהה לפלט של git hash-object <הקובץ המקומי>. אם אינו זהה, דחוף את אותו קובץ שוב, עד שלושה ניסיונות לקובץ. אם אחרי שלושה ניסיונות קובץ אחד עדיין אינו תואם, או שקריאה נחסמה או החזירה שגיאה גם בניסיון חוזר: הפסק את חלק א (אל תדחוף את שאר הפרוסות ואל תנסה דרך אחרת: לא git push, לא כלי אחר, לא ניסוח אחר), השאר את main כפי שהוא (הפעולה לא תפרסם ענף שה-sha256 שלו אינו תואם), המשך לחלק ב, סמן את הריצה partial, וצטט בשורה התחתונה וב-actionRequired את שם הקובץ ואת הודעת השגיאה או החסימה כלשונה (הטקסט המלא שהכלי החזיר, כולל שם הכלי).
7. אימות הפרסום (חובה): כל דחיפה מפעילה את publish-build, והדחיפה האחרונה היא שמפרסמת. המתן 60 שניות, ואז, עד 8 פעמים בהפרשים של 45 שניות: git clone --depth 1 https://github.com/assafbr1/tikim-dashboard.git לתיקייה חדשה, והרץ python3 <שכפול>/tools/verify_site_data.py --dir <השכפול החדש> --password '<הסיסמה>' --expect-sha $(cat <תיקיית הפלט>/data.enc.sha256). שורת OK (ה-sha256 של data.enc.txt ב-main זהה למקומי, הקובץ מתפענח בסיסמה, ובו לפחות 300 תיקים) מסיימת את חלק א בהצלחה; רשום את המספרים שהשורה מדפיסה. אם אחרי כל הניסיונות עדיין FAIL: סמן partial, ובשורה התחתונה וב-actionRequired כתוב מה נכשל ("הפרסום ל-main לא בוצע" או "הקובץ ב-main אינו נפתח בסיסמה") ושאסף יבדוק את הריצה האחרונה של publish-build ב-https://github.com/assafbr1/tikim-dashboard/actions ואת ענף ה-build.
8. כללי ברזל לחלק א: (א) למאגר נדחפים אך ורק הקבצים המדויקים שהסקריפט יצר בריצה הזו, כפי שהם. אסור לדחוף תוכן זמני, ממלא מקום, חלקי, "לניסיון" או מתוקן ביד, ואסור לדחוף שום קובץ אחר (לא index.html, לא app.part*, לא tools). (ב) אין לדחוף ל-main בשום דרך; רק לענף build-*. (ג) אם אי אפשר להעביר פרוסה בנאמנות, עדיף לא להעלות בכלל: main נשאר עם הגרסה הקודמת והריצה מדווחת partial. (ד) בשום שלב אין לדווח הצלחה של חלק א בלי שורת OK מ-verify_site_data.py על שכפול טרי של main.
